# Система генерации kie.ai × Grok Imagine (картинки + видео)

Восстановлено из рабочего пайплайна сессии «Кегель-карусели» (контент Stretcher).
Код — в `kie_grok.py`.

## API в двух словах

- Всё через две ручки: `POST /api/v1/jobs/createTask` и `GET /api/v1/jobs/recordInfo?taskId=`.
- Авторизация: `Authorization: Bearer <KIE_API_KEY>` (ключ проекта — тот же, что
  использовался в прошлой сессии; в файл не зашит, задаётся через env).
- `createTask` возвращает `taskId`; результат опрашивается до `state: success`,
  ссылки лежат в `resultJson → resultUrls`. `state: fail` + `failMsg` — брак/модерация.

## Модели

| Модель | Что делает | Ключевые поля input |
|---|---|---|
| `grok-imagine/text-to-image` | картинка | `prompt`, `aspect_ratio` |
| `grok-imagine/text-to-video` | видео из текста | `prompt`, `aspect_ratio`, `mode`, `duration` (сек, строкой), `resolution` (`480p`…) |
| `grok-imagine/image-to-video` | оживить кадр | либо `image_urls: [url]` (в промпте ссылаться `@image1 …`), либо `task_id` + `index` грок-картинки — **не оба сразу** |
| `grok-imagine/upscale` | апскейл видео | `task_id` видео-задачи |

Удобная связка для видео: сгенерил картинку → передал её `taskId` в
`image-to-video` без перезаливки файла.

## Правила пайплайна (выстраданы прогонами)

1. **Фон и фигуру генерить раздельно.** Цельную композицию «человек в сцене
   делает упражнение» Grok заваливает; склейка кодом (PIL: тень с альфы,
   GaussianBlur, alpha_composite) стабильнее.
2. **Схемы и анатомические диаграммы не генерить** — Grok портит анатомию
   (пальцы, суставы под неестественными углами). Точки/стрелки рисуем сами
   поверх кадра.
3. **Единый персонаж серии** — один и тот же гардероб-префикс во всех промптах,
   иначе каждый кадр — другой человек.
4. **Всегда суффикс** `no text, no watermark, no typography` — иначе Grok сыпет
   надписи в кадр. Текст всегда кладём сами.
5. **Вырез фигур:** фотореализм — `rembg` (u2net), проверять `getbbox` и
   `top_frac`; плоские стикеры на белом — хромакей по белому
   (`gray > 235 → прозрачно`) чище, чем rembg.
6. **Числовой контроль брака:** доля непрозрачных пикселей после выреза
   (норм ~0.2, мусорная изоляция даёт 0.5+), bbox, разрывы обводки — ловит
   брак без глаз.
7. **Пакетный режим:** создать все задачи сразу (пауза ~1 с между createTask),
   сохранить `tasks.json`, опрашивать циклом каждые ~8 с. Упавшие перегенеривать
   точечно по имени.
8. **Баланс не бездонный** — каждая генерация (и каждый брак) списывает кредиты;
   расход считать честно.
